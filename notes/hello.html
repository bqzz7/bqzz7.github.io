把单页拆成多页：这个门户怎么搭的

目录

原来的首页是一整块 HTML，样式和脚本全塞在文件里。它其实挺好看，但每加一个功能就要在那个巨长的文件里找位置，改到第三次我就不想动了。这次的目标很朴素：拆开，但不要变复杂。

为什么不上框架

试过两条路。一条是引入构建工具，换来组件化和 Markdown 写作；另一条是什么都不装，纯手写。选后者是因为这个站的页面数量是可数的（现在是六页加四篇笔记），内容更新频率也不高。为十来个页面配一套 Node 工具链，收益抵不上维护成本。

代价也很直接：导航、页头、页脚要在每个页面各写一遍。我接受这个代价，因为改版时用批量替换就能同步，而且任何一个页面单独拎出来都能直接打开。

目录结构

根目录只放页面和元信息，所有可复用的东西进 assets/：

bqzz7.github.io/
├── index.html        首页
├── works.html        作品（筛选 + 灯箱）
├── notes.html        笔记列表
├── notes/            单篇笔记
├── about.html
├── links.html
├── lab.html          工具箱
├── assets/css/style.css?v=2
├── assets/js/main.js?v=4
├── data/search.json  站内搜索索引
└── legacy/index-v1.html  旧版单页备份

关键是那条 body data-root="../"：子目录页面把根路径写进属性，脚本据此拼出 CSS、索引和跳转地址。只有一处需要改，而且不依赖任何运行环境。

共享样式怎么切分

样式表按用途分十六段，从 tokens 到响应式，每段开头有注释。改颜色只动 :root，深色模式是同一组变量在 [data-theme="dark"] 下的另一份值。因为全站只用这一组变量，切换主题不需要写第二套样式。

经验：先定好颜色、间距、字号三类变量，再写组件。变量没定就动手，后面一定会返工。

脚本的写法

一个 IIFE，十一个小模块：主题、年份、渐显、导航高亮、筛选、灯箱、复制、搜索、目录与进度、工具箱、外链处理。每个模块开头都判断元素在不在，不在就安静跳过。这样同一个 main.js 可以给六种不同的页面用，不用为每页单独写脚本。

举个小例子，搜索索引是懒加载的：打开浮层才请求 search.json，失败就当成空数组，页面其它功能完全不受影响。

无障碍与降级

几条底线：skip link、可见的 :focus-visible、灯箱用原生 <dialog>、动效尊重 prefers-reduced-motion。所有动画都只是"锦上添花"，关掉之后内容照样读得通。

另外，页面在没有 JS 的情况下也能看：渐显的初始状态由 JS 加类触发，没有 JS 就不会有透明度为 0 的段落。这个细节不做，会白屏。
