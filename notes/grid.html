不改代码也能改版式：几个 clamp 的用法

目录

写响应式最容易犯的错，是把每个尺寸都写成一条媒体查询：平板一档、手机一档、小手机再一档。改一次间距就要翻三处。这个站一档都没写，靠的都是 clamp()。

它到底在算什么

clamp(最小值, 理想值, 最大值)。中间的"理想值"通常带视口单位（vw），所以会随窗口线性变化；两头负责兜底，防止在大屏上字大得离谱，或在小屏上挤成一团。

/* 标题：最小 3.6rem，最大 9.4rem，中间随宽度走 */
h1{ font-size: clamp(3.6rem, 12.2vw, 9.4rem); }

12.2vw 是我拿设计稿反推的：在 1440 宽时刚好落在 9rem 附近，到手机宽度时自然收到 3.6rem 左右。不用记断点，看效果调系数就行。

间距比字号更好用

字号还要考虑可读性，间距直接可以放开手脚：

.sec{ padding: clamp(44px, 6vw, 88px) 0; }
.shell{ padding: 0 clamp(20px, 3.4vw, 56px); }

这样小屏不会显得空，大屏也不会挤在中间一条窄带里。另一个常用位置是栅格间隙：

.works{ gap: clamp(22px, 3vw, 40px) clamp(16px, 2.2vw, 28px); }

侧栏宽度也能量出来

左侧固定栏用百分比加夹取，避免在 1280 宽时栏太窄、在 4K 屏上又宽得离谱：

:root{ --rail: clamp(196px, 17vw, 252px); }

配合 calc() 更实用：calc(100% - var(--rail)) 这类算式里，夹取过的变量照样能用。

三个坑

  • 中间值别用 em 混着 vw 算，容易绕晕；统一用 vw 或 rem + vw 的加法。
  • 夹取的上下限要留给"极窄"和"极宽"，中间不要卡太死，否则看起来像没生效。
  • 真正需要换布局的地方（比如三列变一列），还是得用媒体查询。clamp 管尺寸，不管结构。

顺手记一下

我习惯把三个数写在同一行并加注释，半年后回来看还能看懂：clamp(22px, 3vw, 40px) /* 卡片间距 */。这类小习惯，比记住多少属性更值钱。
